# 同址宿主维护与完整恢复点

## 背景

CloudDrive 的 Web Host 和 Go API 会在容器升级中停止。管理员需要在原站点地址查看任务进度并恢复故障实例。现有发布包包含已配对的 API 和 Web 镜像，文件与 SQLite 使用宿主机目录持久化。

## 决定

启用网页运维时，由 systemd 托管的独立网关接管原 Web 端口。网关转发到回环地址上的 Web Host，并独立渲染维护页。宿主维护进程拥有安装账户的 Docker 权限，通过受文件权限保护的 Unix socket 提供受限、类型明确的操作。业务容器继续通过 IAM 识别系统所有者。维护页具备独立认证的恢复入口。

升级使用签名的官方镜像包，保持现有安装目录和既有存储身份。停止写入后创建完整恢复点并持久化阶段记录。旧程序仅在精确兼容当前 schema 时重新启用。需要还原数据时，由操作人确认恢复点，校验和暂存通过后再切换目录。

## 后果与退出条件

启用需要宿主机管理权限和可用的 systemd。完整恢复点增加停机时间与磁盘消耗。远程写操作需要可信的 HTTPS 入口。其他部署继续使用原 CLI。若将来需要改变网关或运行时，先验证现有 Web 地址、CLI、版本配套、持久化路径与恢复点兼容，再迁移宿主控制面。
