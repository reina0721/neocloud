# 原生 Web 与 Go 成对发布

## 决定

原生生产使用 Next.js 静态导出。Go 宿主提供页面、版本化资源和导航数据，并将接口与文件协议请求分派到当前业务进程。Go 业务进程继续负责会话、授权、外部阅读器策略、WebDAV 和数据库。开发入口使用 Next 热更新与 Go 双进程。

整包签名绑定平台、Go 版本、源码提交与静态文件清单。宿主在已准备的 Go 与 Web 都可用时提交同一份版本记录，并同步切换路由。当前和上一完整版本可以读取自己的版本化资源。旧标签页提示用户刷新，现有离开守卫负责未保存表单。后台操作先使用现有 IAM 系统所有者与写入证明，再通过宿主本机控制通道提交任务。

旧托管实例首次接管需要精确兼容的无迁移整包。接管成功后使用旧宿主无法误读的状态格式。初次接管失败时保留原有版本选择。独立 Go、整包和容器产物各自保有对应的安装契约。

## 验证边界

发布前对真实静态输出、三平台进程、签名附件和现有数据做独立检查。首次发布没有旧整包时记录夹具覆盖。改变公开地址、跨主机发布或删除上一版资源前重新验证回退与旧标签页行为。
